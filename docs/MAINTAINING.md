# Maintain the public kit

This is a text-based coaching project. The user interface is the user's Claude or ChatGPT app. There is no web server, hosted frontend, API key, database, or deployment step.

## Canonical sources

- `skills/personal-training-coach/SKILL.md`: shared operating contract and routing.
- Other `skills/*/SKILL.md`: focused coaching workflows.
- `docs/PROJECT-INSTRUCTIONS.txt`: short instructions to paste into an app.
- `README.ru.md`, `START-HERE.ru.md`, and `docs/*.ru.*`: Russian user guides and project instructions.
- `templates/MY-TRAINER.ru.md`: Russian notebook prose with the original machine-readable table schema.
- `templates/MY-TRAINER.md`: blank chat notebook.
- `templates/workspace/`: blank private folder structure.
- `scripts/public_manifest.py`: explicit list of public build inputs and allowed repository files.
- `starter/`: generated beginner downloads. Never add personal records or edit generated files directly.
- `agent.jsonl`: generated ChatGPT knowledge bundle; it is not a replacement for `AGENTS.md` or pasted project instructions.
- `.claude/skills/personal-training-coach/`: generated repository-native Claude Code package.
- `research/`: public, generic, source-linked briefs; personal research belongs in the private workspace.
- `scripts/audit_week.py`, `scripts/analyze_weight_history.py`, `scripts/records.py`: portable read-only analysis.
- `scripts/import_research.py`: explicit private source preservation with a hash and unverified import note.

The handbook combines seven skill sources, supporting references, the research library, and reusable prompts, replacing local document links with anchors. The beginner path uploads the readable handbook; an identical .txt copy handles apps that reject .md. `agent.jsonl` is an optional package of the same sources. `starter/CLAUDE.md` combines instructions and handbook for Claude Projects. `starter/ru/` is built with Russian project instructions and notebook prose, plus the same English workflow and research sources. The Claude ZIP and `.claude/skills/` tree contain the same self-contained skill with the handbook and portable tools. Every input is explicitly listed; packaging never discovers private records.

## Keep English and Russian in sync

Update each pair in `TRANSLATION_PAIRS` together, including screenshots or model guidance if added later. Review the two beginner paths from downloading files through a fresh chat reading the saved notebook. Keep user-facing prose and copyable prompts in the selected language. Shared internal research is English in both bundles; do not label those references as fully translated. Generated byte comparisons ensure neither language loses sources.

After reviewing both sides, update `docs/translation-review.json` with the review date and SHA-256 of each paired source's UTF-8 text with LF line endings. The builder deliberately does not refresh this record. `check_public.py` fails if either language changes afterward. Hashes detect drift; they do not assess translation quality or substitute for bilingual review. Keep structured notebook headings, column names, status values, date and numeric formats, and unit codes compatible with the analytics tools.

## Build and check

Python 3.10+ is the only development dependency. From the repository root:

```text
python scripts/build_starter.py
python scripts/build_starter.py --check
python scripts/check_public.py
python -m unittest discover -s tests
git diff --check
```

On Windows, use `py` if needed. No package installation is required. The generated ZIP uses fixed timestamps, and JSONL uses deterministic record order, so rebuilds are reproducible. The builder reads only explicit public sources, refuses symlinked sources/output paths, and never reads `personal/` or another repository.

Tests cover initialization without overwriting records, public packaging that excludes private canary data, deterministic output, portable skill contents, privacy-check failures, unit conversion, model behavior, nutrition denominators, workload projections and duplicates, source import integrity, and execution from an extracted package. The checker evaluates tracked and visible untracked files; it also catches a private file that someone force-added to Git. It cannot identify all sensitive natural-language content. Review the actual diff before publishing.

## Add a public file

Add it intentionally to `PUBLIC_FILES` (or the appropriate source list) in the manifest. New root directories are ignored unless explicitly allowed in `.gitignore`. Never broaden packaging to recursively include the working directory. Keep templates blank and use synthetic records only in isolated tests. Do not copy an existing athlete's plans or logs into examples.

Changes to skills should also be checked with a skill validator when one is available. Behavioral review matters more than frontmatter validity: follow the scenarios in [COACHING-SCENARIOS.md](COACHING-SCENARIOS.md). App integration still needs a manual smoke test in the target account; static checks cannot prove instruction following, current account features, or persistence.
