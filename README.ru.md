# Стартовый проект AI Personal Trainer

[English version](README.md) | **Русская версия**

Проект для начинающих, который помогает научиться использовать ИИ для организации тренировок, целей, расписания и заметок о прогрессе с помощью обычных текстовых файлов.

> **Начните отсюда:** этот публичный репозиторий — учебный стартовый проект. Его можно использовать тремя способами: **(1) сделать публичный форк для экспериментов или участия в проекте, (2) создать отдельную приватную копию на GitHub для личного использования или (3) хранить всё только в локальной папке на своём компьютере, вообще без репозитория GitHub.** Никогда не добавляйте реальные личные, медицинские, школьные, контактные или другие чувствительные данные в публичный форк или публичный репозиторий.

Это руководство рассчитано на людей, которые почти ничего не знают об ИИ, GitHub и разработке программ. **Программистом быть не нужно.**

---

## Что делает этот проект

Идея простая:

1. Ваша информация хранится в понятных Markdown-файлах (файлах с расширением `.md`).
2. Если вы используете GitHub, он помогает организовать файлы и сохраняет историю изменений.
3. ИИ-помощник может читать файлы, помогать составлять план, обновлять журналы и объяснять, что изменилось.
4. Запланированные тренировки хранятся отдельно от выполненных, чтобы ИИ случайно не выдал запланированное действие за реально выполненное.

Можно представить этот проект как умный тренировочный блокнот с очень аккуратной системой папок.

Это инструмент для обучения и организации. Он **не заменяет врача, физиотерапевта, диетолога или экстренную медицинскую помощь**.

# Выберите, как вы хотите использовать проект

Единственного обязательного способа нет. Выберите вариант, который подходит именно вам.

## Вариант 1 — Публичный форк

**Форк** — это ваша собственная копия проекта на GitHub, которая остаётся связанной с исходным публичным репозиторием.

Используйте форк, если вы хотите:

- экспериментировать с публичным проектом;
- предлагать улучшения;
- учиться пользоваться GitHub;
- сохранять связь своей версии с исходным проектом.

**Важно:** форк этого публичного репозитория тоже будет публичным. **Не добавляйте** туда реальные журналы тренировок, медицинскую информацию, школьные данные, адреса, личные контакты, пароли или API-ключи.

Этот вариант лучше всего подходит для **демонстрационных данных, учебных примеров и участия в развитии проекта**, а не для реального личного тренировочного дневника.

## Вариант 2 — Отдельная приватная копия на GitHub

Это хороший вариант, если вам нужны:

- приватное хранение;
- история изменений GitHub;
- доступ с нескольких компьютеров;
- резервное копирование и синхронизация через GitHub;
- возможность работать с репозиторием через Codex и GitHub.

Такая копия должна быть **новым приватным репозиторием, а не публичным форком**.

## Вариант 3 — Только локальная папка, без GitHub

Это самый простой вариант, если вы хотите, чтобы файлы хранились только на вашем компьютере.

Вы можете:

1. Скачать стартовый проект как ZIP-файл.
2. Распаковать его в обычную папку, например `Documents/AI-Personal-Trainer`.
3. Открыть эту папку как локальный проект в приложении, CLI или IDE, где Codex умеет работать с локальными файлами.
4. Разрешить ИИ читать и редактировать Markdown-файлы в этой папке.
5. Самостоятельно делать резервные копии папки.

Для этого варианта вам **не нужны** аккаунт GitHub, репозиторий GitHub, хостинг сайта, база данных или доменное имя.

Минус в том, что GitHub не будет автоматически давать удалённую резервную копию и веб-историю версий. За резервное копирование отвечаете вы. При желании позже можно использовать Git локально, не публикуя проект на GitHub.

## Какой вариант выбрать?

| Способ | Для чего подходит | Можно хранить личные/приватные данные? | Нужен GitHub? |
|---|---|---:|---:|
| **Публичный форк** | Обучение, демо, участие в проекте | **Нет** | Да |
| **Отдельная приватная копия GitHub** | Личное использование с синхронизацией и историей | Да | Да |
| **Только локальная папка** | Личное использование на компьютере, самый простой способ хранения | Да, если компьютер нормально защищён | **Нет** |

Если проектом пользуется ребёнок, родитель, опекун, учитель или тренер должен помочь выбрать подходящий вариант и решить, какую информацию вообще стоит сохранять.

# Словарь для начинающих

Нужно знать всего несколько терминов.

### Репозиторий (repository, repo)

Репозиторий — это папка проекта, которая хранится на GitHub.

### Публичный репозиторий

Его может просматривать любой пользователь интернета. Используйте публичные репозитории только для примеров, инструкций и информации, которую вы готовы опубликовать.

### Приватный репозиторий

Его видите только вы и люди, которым вы явно дали доступ. **Для реальных личных тренировочных данных используйте приватный репозиторий или защищённую локальную папку.**

### Markdown

Markdown — это обычный текст с простым форматированием. Такие файлы обычно заканчиваются на `.md`.

Пример:

~~~md
# Моя цель

Я хочу научиться пробегать 1 милю без остановки и тренироваться три раза в неделю.
~~~

### Commit / коммит

Коммит — это сохранённая контрольная точка. Она позволяет увидеть, что изменилось, и при необходимости вернуться к более ранней версии.

### Запрос к ИИ / prompt

Prompt — это просто инструкция или вопрос, который вы даёте ИИ.

### AGENTS.md

Это специальный файл с инструкциями, который объясняет ИИ-агенту, как он должен вести себя при работе с проектом.

Можно считать его **сводом правил проекта**.

# Шаг 5 — Дайте ИИ первую задачу по настройке

Если в вашей приватной копии GitHub или локальной папке ещё нет стартовой структуры, вставьте следующий запрос в Codex.

~~~text
Я создаю приватное рабочее пространство для персональных тренировок с помощью ИИ.

Пожалуйста, создай простую и понятную новичку структуру на основе Markdown-файлов.

Создай:
- AGENTS.md
- profile/goals.md
- profile/availability.md
- profile/training-preferences.md
- profile/equipment.md
- profile/constraints.md
- schedule/current.md
- templates/workouts/
- logs/workouts/
- logs/check-ins/
- research/

Правила:
1. Храни запланированные тренировки отдельно от журналов выполненных тренировок.
2. Никогда не придумывай выполненную тренировку, измерение, симптом, приём пищи или результат.
3. Спрашивай перед серьёзным изменением уже принятого плана.
4. Используй простой и понятный язык.
5. Объясняй каждый созданный или изменённый файл.
6. Не добавляй личную информацию, которую я явно не предоставил.
7. Не сохраняй пароли, API-ключи, адреса, школьную информацию или данные учётных записей.
8. Если спортсмен несовершеннолетний, отдавай приоритет соответствующим возрасту тренировкам, навыкам, регулярности, удовольствию, восстановлению и участию взрослого.
9. Не создавай для несовершеннолетнего планы снижения веса, жёсткого ограничения питания, приёма добавок или медицинского лечения.
10. Если возникает боль, травма, болезнь или другая медицинская проблема, укажи, что её нужно обсудить с родителем/опекуном и подходящим медицинским специалистом, а не относись к ней как к обычной тренировочной трудности.

Перед созданием первого тренировочного плана спроси только минимально необходимую информацию:
- возрастной диапазон;
- тренировочную цель;
- уровень опыта;
- доступные дни;
- доступное время на одну тренировку;
- имеющееся оборудование;
- виды спорта/активности, которыми человек уже занимается;
- травмы или ограничения, которыми я сам решу поделиться;
- всё, что родитель, опекун, тренер или медицинский специалист рекомендовал избегать.

Не запрашивай ненужные идентифицирующие данные.
~~~

Просмотрите предложенные ИИ изменения перед тем, как их принять.

# Шаг 6 — Заполните профиль

ИИ может помочь заполнить несколько простых файлов.

Пример профиля для начинающего:

~~~md
# Цели

- Улучшить общую физическую форму
- Научиться пробегать одну милю без остановки
- Освоить хорошую технику приседаний, отжиманий и планки
- Тренироваться 3 дня в неделю
~~~

Пример файла с оборудованием:

~~~md
# Оборудование

Есть:
- Свободное место на полу
- Резиновые эспандеры
- Лёгкие гантели
- Беговая дорожка

Нет:
- Штанга
- Сани
- Гребной тренажёр
~~~

Пример расписания:

~~~md
# Текущее расписание

Понедельник: 30 минут силовой тренировки для начинающих
Среда: 25 минут лёгкого кардио + мобильность
Суббота: 35 минут смешанной тренировки
~~~

Вам не обязательно писать эти файлы вручную. Можно сообщить ИИ факты обычным языком и попросить разложить их по нужным файлам.

# Простая структура папок

Хороший вариант для начинающих выглядит так:

~~~text
my-training-workspace/
├── README.md
├── AGENTS.md
├── profile/
│   ├── goals.md
│   ├── availability.md
│   ├── training-preferences.md
│   ├── equipment.md
│   └── constraints.md
├── schedule/
│   └── current.md
├── templates/
│   └── workouts/
├── logs/
│   ├── workouts/
│   └── check-ins/
└── research/
~~~

### Что означает каждая папка

- `profile/` — медленно меняющиеся факты: цели, расписание, предпочтения, оборудование и ограничения.
- `schedule/` — то, что запланировано сейчас.
- `templates/` — повторно используемые шаблоны тренировок.
- `logs/workouts/` — то, что реально было выполнено.
- `logs/check-ins/` — короткие заметки об энергии, болезненности мышц, сне или ощущениях от тренировки.
- `research/` — полезные статьи, правила или исследовательские заметки ИИ, которые могут повлиять на будущие решения.
- `AGENTS.md` — правила, которым должен следовать ИИ.

Главная идея:

> **План = то, что должно произойти. Журнал = то, что действительно произошло. Никогда не смешивайте их незаметно.**

# Как использовать проект каждый день

С ИИ можно разговаривать обычным языком.

## Перед тренировкой

~~~text
Прочитай моё текущее расписание и профиль. Какая у меня сегодня тренировка?
Объясни её так, чтобы понял новичок.
Не меняй план, если я об этом не прошу.
~~~

## Если оборудование недоступно

~~~text
Сегодня беговая дорожка недоступна.
Проверь мой файл с оборудованием и предложи безопасную замену сегодняшнему кардио.
Не переписывай весь недельный план.
~~~

## После тренировки

~~~text
Я выполнил сегодняшнюю тренировку.

Фактически:
- 5 минут разминки
- 3 круга по 8 приседаний goblet squat
- 3 круга по 6 отжиманий с опорой
- 3 × 20 секунд планки
- 10 минут лёгкой ходьбы

Сложность: 5/10
Боли не было.

Создай журнал сегодняшней тренировки.
Не меняй исходный план так, будто я выполнил что-то другое.
~~~

## Если тренировка выполнена только частично

~~~text
Я остановился после второго круга, потому что закончилось время.
Запиши только то, что я действительно выполнил.
Не отмечай невыполненную часть как завершённую.
~~~

## Еженедельный обзор

~~~text
Сравни запланированные тренировки этой недели с реальными журналами тренировок.
Покажи:
- что было запланировано;
- что было выполнено;
- что было пропущено или изменено;
- что ощущалось лёгким или сложным;
- какие закономерности стоит обсудить.

Пока не меняй план на следующую неделю.
Предложенные изменения покажи отдельно, чтобы я сначала мог их одобрить.
~~~

# Как проверять изменения, сделанные ИИ

ИИ может ошибаться.

Перед принятием важных изменений:

1. Прочитайте краткое описание того, что ИИ изменил.
2. Откройте изменённый файл.
3. Убедитесь, что ИИ не придумал тренировку, результат, симптом или личный факт.
4. Убедитесь, что запланированная работа не была переписана как выполненная.
5. Проверьте, что не добавлены секреты или идентифицирующая информация.
6. При изменении тренировки спросите: «Почему ты это изменил?»
7. Если что-то выглядит неправильно, попросите исправить это до сохранения.

Понимать программный код не обязательно. Большая часть проекта — обычный текст.

# Проверка приватности

Перед сохранением файла спросите себя:

- Есть ли здесь пароль или API-ключ? **Не сохраняйте его.**
- Есть ли здесь домашний или школьный адрес? **Не сохраняйте его.**
- Есть ли здесь номер телефона или личная электронная почта? Обычно **не сохраняйте их**.
- Есть ли здесь полное юридическое имя ребёнка или дата рождения? Избегайте этого, если нет реальной необходимости.
- Есть ли здесь медицинская информация? Храните её приватно и делитесь только тем, что действительно необходимо.
- Если я использую GitHub, точно ли личный репозиторий отмечен как **Private**?
- Если я использую локальную папку, достаточно ли защищён компьютер/учётная запись и есть ли резервная копия?
- Готов ли я к тому, что любой человек с доступом к репозиторию, папке, устройству или резервной копии увидит эту информацию?

Полезный проект не требует большого количества личных данных.

# Частые проблемы

## «Я не вижу свой репозиторий в Codex или ChatGPT»

Проверьте:

1. Вы вошли в правильный аккаунт GitHub.
2. Приложение OpenAI/ChatGPT на GitHub имеет доступ к приватному репозиторию.
3. При авторизации выбран правильный репозиторий.
4. После создания или выдачи доступа иногда нужно немного подождать.

---

## «ChatGPT может читать файлы, но не может их менять»

Возможно, вы используете обычное подключение GitHub в ChatGPT.

Оно в основном предназначено для чтения и анализа содержимого репозитория.

Когда нужно создавать, редактировать и отправлять изменения в файлы репозитория, используйте **Codex**.

---

## «Я исчерпал лимит ИИ»

На бесплатном плане такое возможно.

Можно:

- дождаться сброса лимита;
- при желании перейти на платный план ChatGPT, чтобы получить больше использования.

Не нужно покупать API-ключ только потому, что закончился лимит начального плана.

---

## «ИИ изменил слишком много»

Скажите:

~~~text
Не делай широких изменений.
Покажи точно, какие файлы ты хочешь изменить и почему.
Больше ничего не меняй.
~~~

Также можно попросить восстановить предыдущую версию с помощью истории Git, если вы её используете.

---

## «ИИ утверждает, что я выполнил то, чего я не делал»

Исправьте это сразу:

~~~text
Это было запланировано, но не выполнено.
Удали это из журнала фактических действий.
Никогда не делай вывод о выполнении только на основании расписания или шаблона.
~~~

После этого убедитесь, что в `AGENTS.md` есть правило: выполненная активность может появляться в журнале только из явного сообщения пользователя или другого доверенного источника.

---

## «Я случайно добавил личную информацию в публичный репозиторий»

Считайте, что эта информация могла стать доступной другим людям.

1. При необходимости сразу сообщите родителю/опекуну, учителю, владельцу проекта или администратору.
2. Если вы контролируете репозиторий, немедленно сделайте его приватным.
3. Удалите информацию.
4. Помните, что более ранние версии могут сохраняться в истории Git.
5. Если был опубликован пароль, токен или API-ключ, немедленно смените или отзовите его.
6. Если информация чувствительная, попросите помощи у человека, который понимает историю GitHub.

# Рекомендуемые правила для ИИ

Со временем ваш `AGENTS.md` должен включать примерно такие правила:

1. Никогда не придумывать выполненную активность.
2. Хранить планы отдельно от фактических журналов.
3. Спрашивать перед серьёзными изменениями плана.
4. Объяснять важные изменения простым языком.
5. Учитывать реальное оборудование и расписание пользователя.
6. Не переписывать старые журналы незаметно.
7. Беречь личную информацию.
8. Отдельно отмечать боль, травму, болезнь и другие проблемы со здоровьем.
9. Для несовершеннолетних избегать жёстких диет, небезопасных нагрузок и максимальных усилий без надзора.
10. Считать предложения ИИ именно предложениями, которые должен проверить человек.

# Как обновлять личную копию

Отдельный приватный репозиторий или локальная копия не будут автоматически получать будущие улучшения стартового проекта. Публичный форк остаётся связан с исходным проектом, но помните: он остаётся публичным.

Безопасный способ обновления:

1. Проверьте публичный стартовый проект на наличие новых инструкций или примеров.
2. Попросите Codex сравнить стартовый проект с вашим приватным репозиторием или локальной папкой.
3. Скажите ему **не перезаписывать ваш профиль, расписания и журналы**.
4. Просмотрите предлагаемые обновления структуры или инструкций.
5. Принимайте только те изменения, которые вы понимаете и действительно хотите.

Пример запроса:

~~~text
Сравни текущую структуру публичного стартового проекта с моим приватным тренировочным рабочим пространством.
Предложи только полезные обновления структуры или инструкций.
Не копируй личные демонстрационные данные.
Не перезаписывай мой профиль, расписание, журналы или записи о выполненных тренировках.
Сначала покажи предлагаемые изменения, а уже потом применяй их.
~~~
